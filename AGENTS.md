# verified

verified is the champäne of agents. It attempts to build a proven correct agent : https://chezdodds.dev/blog/verified-preregistration/.

It builds a modern agent harness oriented around safety and correctness. 

The project follows the traditional RFC process and this contains the record of design decisions in docs/rfcs. `docs/rfcs/0002-api.md` is a draft of the public API: a proposal that overrides neither this file nor `PRINCIPLES.md`.

Prefer straightforward designs and delete accidental complexity rather than preserving it.

v controls **dispatch**: what runs, when, with whose approval, at most once, with exactly one recorded result. It does not control the filesystem or the OS. Tools act on the world best-effort and report honestly. Containment is a future sandbox `Env`. `PRINCIPLES.md` sets out what v upholds and what it doesn't, and the admission rule a new promise must pass. Read it before adding or changing any guarantee.

This repository is a Rust workspace. Each crate under `crates/` sits on a real architectural boundary:

- `verified-domain`: the domain types every other crate shares: ids (an actor's `ActorId`; `TurnId` and `TaskId` are seqs of the log), envelopes and addresses (`user`, `v`, an actor), records, outcomes (`Exit`: `Ok`, `Failed`, `NotStarted`, `Unknown`), tools (`Tool::ALL`, the one list of them) and their classes (`Safe`, `Unsafe`, `Keyed`), a call's shape (tool, subject, and whether it starts a task, spawns a child or cancels a task), grants and rules, an actor's birth (`Born`), the compaction records (`CompactionStarted`, the cut, durable before the summarize call; `Compacted`, its summary and the actor's `OpenWork`, which the core writes and the model never does) with the built-in summarize `INSTRUCTION`, limits and the payload trait. It holds types and pure helpers, written inside `verus!{}` so the core's proofs can talk about them, and the call table (`named`), plain Rust outside `verus!{}` that pairs each record with the proposal it names.
- `verified-core`: the sans-io core (`decide`, `apply`, `recover`, `resume`), the mailbox (`mailbox`: envelopes delivered and not yet carried; a model call carries the batch at its head, a user's message alone or the run of other envelopes before it) and the rules matcher (`rules::grant`, the first rule that fits a call). It is pure, sync and written inside `verus!{}`, and `just verify` checks it with Verus. An actor is born once (`resume` records the shell's `Born`); envelopes land as `Delivered` and start a turn when the actor is idle, or wait for the running one's next step boundary; while a user's message waits, no call of the step waits for the user (each is denied, "the user steered"); a background call (`bash` in the background, `wake`) resolves at its start and runs on as a task, bound to the call that started it, whose `TaskEnded` is its notification; a `cancel` of a task is recorded on it, so it is signalled once; a stop always lands unless the child's log refuses it (the message limit bounds mail only), revokes everything and sends `stop` to every child (`StopSent`, a `Keyed` task); after a crash, `Safe` and `Keyed` calls rerun under their key only while their turn proceeds (under a cancel or a stop they resolve `Unknown`), and a stopped actor reruns only its stops. Model history compaction (not log compaction: the log and the transcript keep everything, only what the model is sent shrinks) is the core's to decide and the shell's to run. The cut is always now, at a beat with every call resolved, so unread mail is never inside it. A turn compacts when its next step will not fit (forced, inside the turn, at most once a beat: if the summary does not make room the turn ends `Failed(Context)` and the actor parks, with no retry until the next envelope or `/compact`); an actor compacts between turns when a turn leaves its context past 80% and no mail waits, or on the user's `/compact` (refused while a turn runs), and a turn that starts supersedes it. A summarize call (`Effect::Summarize`) is v's housekeeping: no turn, no grant, no mail consumed, and the same token budget as a step's call. A crash leaves a dangling `CompactionStarted`, and resume compacts again; `Compacted` resets the context to the summary and the open work. Every grant is the user's approval command or a rule in force (`RulesLoaded`); `decide` records a user's grant only on the user's approval command and a run's report only as it came (`honest`). The rules file is `.verified/v.toml`; the shell reads it (`rules_file`, through the `Env` seam) at every boot, before every delivery to an actor and before each model response is settled, and records it when its text changes. With no file the one rule is `read: allow`.
- `verified-model`: the Stateright model of the core in an abstract world (`Harness`). The world holds several actors, each the real core on its own log under one daemon (a crash cuts every actor's pending writes to some prefix of each), with deliveries between logs (a `send`, a `spawn`: the child's log, its `Born`, its prompt; a stop and its cascade, a stop with no deadline and waiting for its child's spawn in flight), background tasks and timers, steering, runs that never report (`Hang`) and the shell's deadline (`Expire`), and the registry's cap on actors. BFS explores it over a small domain (`Bounded`, which also bounds the world's faults); trace mode (`Harness::trace`) takes its actions' ids and sizes from a trace, and `replay` (or `replay_actors`, each observation tagged with its actor) walks a run's observations through it one state at a time (each observation names the actions it means, and every `always` property is checked on each state). It also holds α (`alpha`) for records, events and effects, the abstraction from any payload to the model's `Abstract`. Its `suite` holds the bounds every model check runs under, and `coverage` keys each step of the model small (a call's class, how far it got and how it resolved; a crash against a run's act; a few situations) for BFS's edges (`coverage::explore`) and a replay's steps alike. Its tests hold the model checks, their planted bugs, and the property test that the core commutes with α.
- `verified-wire`: the types the daemon and TUI share: commands (actors addressed by id, a stop among them; the actor list reply), AI SDK UI chunks plus the actor data chunks (`data-envelope` when mail lands, `data-step-carries` when a step consumes it, `data-task-start` and `data-task-end`, turn start and end), the transcript fold (turns with the envelopes each step carried, the mail still queued, the tasks), SSE and Durable Streams.
- `verified-server`: the daemon. It holds the async shell, the seams (model, log, environment, clock, entropy), the actor registry and the HTTP routes. Actors are sessions: the registry (`daemon::Registry`) hosts one log per actor under `.verified/actors/`, rebuilds itself at boot, caps the actors (`ServerLimits::actors`), lists a child once its birth is durable and never awaits a session. A root actor the user makes is born `main`, offered every tool; a spawned child is born as its parent's `spawn` named it. The shell delivers envelopes (`ActorHandle::deliver`) and the user's messages alike, to an idle or a busy actor (a message to a busy actor steers its turn), answering only once the `Delivered` is durable; a message that would start no turn (the actor idle at its turn limit) or that the actor has no room for is refused before anything is recorded, and one to a log a crash left unborn is refused as to no actor. Calls are parsed at the model boundary (`payload::Boundary`: the actor's tools, and the Clock and Entropy that mint a timer's deadline and a child's id before `StepFinished` records them). A background `bash` runs as a task under `task_timeout`, a `wake` sleeps until its durable deadline, `tasks` lists the actor's tasks from its projection, and `send`, `spawn` and stops are delivered between logs by `outbox` (one path for all three, each delivery its own task, its envelope id minted from the licensing record's seq, so a rerun lands once; a spawn that made its child is never `NotStarted`). Every run but a timer's, `tasks`' and `cancel`'s has a deadline (`ServerLimits::deadline`) past which the shell reports `Expired` (P1); a stop has none, is sent until it lands, and waits for its parent's spawn of that child in flight (C2). A log that refuses an append, at its own cap or on a full disk, fails stop (T1). The rules file `.verified/v.toml` is read through the `Env` seam (`rules_file`). The routes are what the TUI uses (`/actors` and `/actors/{id}/…`: the commands, your stop among them, the actor list with each actor's waiting approvals and running tasks, answered from each session's live core and projection, and its stream as SSE from an offset); the projection maps records to chunks and keeps what an actor's summary and its `tasks` listing need. A summarize call (`SummaryTask`) is sent the history so far with the instruction after it (`history::summarize`), under a step's `model_max_tokens`; it keeps only text, within `summary_bytes`, and Esc and stops cancel it. The history starts from the latest `Compacted` at its cut (the summary and the open work, as the user's), and still reads the whole log for the mail no step carried yet. `/compact` is `POST /actors/{id}/compact`. The plants that tamper with a decision (`Planted`, `sim` only) live in `shell/planted.rs`; the one-line plants sit where their bug would be. A web client gets the full Durable Streams protocol when it arrives.
- `verified-tui`: the terminal client, an Elm-style loop that follows one actor's stream: an actor tree on top (refreshed on a tick; Tab and Shift-Tab follow another actor, and approvals, Esc and Ctrl-K, a stop once `y` confirms it, go to the one followed), a panel of its running tasks, and messages typed while a turn runs sent at once to steer it (queued until a step carries them). While an approval waits, `y` and `n` answer it on an empty draft; anything else is typed, and Enter sends it, which denies the waiting calls. Enter on `/compact` compacts the actor followed instead of sending a message; the transcript marks where the latest compaction fell.
- `verified-sim`: deterministic simulation tests on turmoil. Only this crate enables the `sim` feature. A seed draws v0's single-actor turns, then may add actors (turns that spawn, send, run in the background, wake, list and cancel tasks, under a rules file that grants children their tools; the fake model runs scripts of several steps), a message that steers a running turn, a crash aimed at a delivery and your stop of the root. The world checks (`check`, I5 to I16) judge every actor's log from the ledger (I14 that each model call's request tells what its step carried, from the shell's sim-only `Requested`; I15 by its own table of deadlines), and the fake provider refuses a malformed conversation (I13). Every run is also replayed through `verified-model`: the ledger, with the shell's sim-only observations (`shim::observe`), is folded into the model's `Observed` facts, each of its actor (a fake `hang` as a hung run), and replayed over every actor's log (`replay_actors`); a run the model cannot follow fails. Some seeds shrink the context (with a long message, a `/compact`, a crash aimed at a summarize call), so histories are compacted: the replay requires each summarize call's `CompactionStarted` durable before it is sent (T1, `Barrier::Summarizing`), and I10, I13 and I14 judge every run across its compactions (I10 exempts a parked actor). Each `Planted` shell bug has a DST test that fails its check; the history's `CutSwallowsMail` (I14) and `CutMidStep` (I13) guard the cut. The replay checks the offsets the TUI read and when; what it folded there is the invariant I6's to check. `just coverage A B` prints the coverage keys BFS reaches under the suite's bounds against those seeds `A..A+B` and the directed scenarios reach, each gap classified (over-approximation, fidelity gap, test gap). A directed scenario (`directed`) is a literal scenario that reaches a gap no seed does: a BFS witness written out as the user's turns and answers, with the one ordering no seed promises (two runs acting together, or an interrupt durable before a run starts) kept by a barrier (`Scenario::hold`). `directed::run` fails one whose replay misses its target.
- `verified-cli`: the one binary, `verified`, which runs the TUI or the daemon (`verified daemon`).

Add a crate only when the code has a new boundary of this kind; do not create speculative crates. Every crate must inherit workspace package metadata and lint configuration.

Nondeterminism enters through explicit seams: `clippy.toml` bans direct use of wall and monotonic time, randomness, the filesystem, environment variables, hash-ordered collections, and unannotated interior mutability. Pass these in as data or through a seam; when an exception is genuinely needed, use `#[expect(..., reason = "...")]`, never `#[allow]`.

Run `just ci` before committing changes. Keep local and CI validation on the same path.

The development environment uses Rust Glancer rather than rust-analyzer. Glancer requires the `rust-src` toolchain component and is provided by devenv as `rust-glancer`.

devenv also provides Verus (`nix/verus.nix`). Verus pins its own rustc, separate from `rust-toolchain.toml`, and only verification runs on that toolchain. To upgrade Verus, bump the release and its hashes in `nix/verus.nix`, the `vstd` pin in `Cargo.toml`, and the toolchain in `devenv.nix` together.
